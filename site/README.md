# The GoCD Lens website

A single static page. No framework, no build step, no dependencies — the same rule the extension
follows. `index.html` and `styles.css` are the whole thing; everything in `img/` is generated.

```
site/
  index.html     the page
  styles.css     the page's styles
  llms.txt       a plain-text summary for answer engines
  robots.txt     indexing rules + sitemap pointer
  sitemap.xml    one URL
  img/           generated by `npm run site` -- do not hand-edit
```

## Regenerating the images

```sh
npm run site     # writes site/img/*.png, including the 1200x630 og.png
```

They are real renders of the extension's own pages against fixture data, produced by
[`tools/make-screenshots.mjs`](../tools/make-screenshots.mjs). `og.png` is the card that Slack,
Teams, X, LinkedIn and search results show.

## Deploying to Vercel

The repository root holds [`vercel.json`](../vercel.json), which points Vercel at this folder. So:

1. Import the GitHub repository at [vercel.com/new](https://vercel.com/new).
2. Framework preset: **Other**. Leave the build command empty — `vercel.json` sets
   `outputDirectory` to `site`, and there is nothing to build.
3. Deploy. Every push to the default branch redeploys.

Locally:

```sh
cd site && python3 -m http.server 8000     # then open http://127.0.0.1:8000
```

## Before the first real deploy — change the domain

The canonical URL is written into five places, all currently `https://gocd-lens.vercel.app`. If
you use a different domain, change all five or search engines will index the wrong host:

| File | What to change |
|---|---|
| `index.html` | `<link rel="canonical">`, `og:url`, `og:image`, `twitter:image`, and `url` in the SoftwareApplication JSON-LD |
| `robots.txt` | the `Sitemap:` line |
| `sitemap.xml` | `<loc>` |
| `llms.txt` | nothing — it only links to GitHub |

```sh
# after picking a domain
grep -rl 'gocd-lens.vercel.app' site/ | xargs sed -i '' 's|gocd-lens.vercel.app|your-domain.com|g'
```

## After the first deploy, check these

- **Link preview** — paste the URL into Slack. If no card appears, `og:image` is pointing at a URL
  that does not resolve.
- **Rich results** — run the URL through
  [Google's Rich Results Test](https://search.google.com/test/rich-results). Both the
  `SoftwareApplication` and `FAQPage` blocks should be detected. The deployed Content Security
  Policy sets `script-src 'none'`; `application/ld+json` is a data block rather than executable
  script, so it is unaffected, but this is the check that proves it.
- **Search Console** — add the property and submit `sitemap.xml`.

## When the Chrome Web Store listing goes live

`index.html` has a comment in the install section marking exactly what to replace with the
**Add to Chrome** button and the store URL. The FAQ, the JSON-LD `featureList` and `llms.txt`
should not need to change.
